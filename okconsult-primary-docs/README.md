# Первинка

Прототип системи обробки первинної документації для бухгалтерського аутсорсингу.
Зібраний під обов'язки з вакансії **«Бухгалтер з первинної документації»**
(ОК, Консалтингова компанія, ТОВ, Київ; 2 000 документів/місяць; 1С, BAS, M.E.Doc, Вчасно).

> **Статус вакансії.** На момент збирання прототипу оголошення на robota.ua позначене як
> закрите (завершене 06.08.2026). На технічну частину це не впливає — задача типова для
> будь-якого бухгалтерського аутсорсингу, — але для будь-якої розмови з цією компанією
> це треба враховувати: людину, найімовірніше, вже найняли, і мова буде не про заміну
> найму, а про зняття рутини з наявного спеціаліста.

## Після відкриття прототипу

Відкрийте `prototype/index.html` подвійним кліком. Інтернет не потрібен: файл
самодостатній, нічого назовні не надсилає, дані живуть у пам'яті вкладки.

Той самий прототип опублікований як сторінка — зручно надсилати посиланням:
**https://claude.ai/code/artifact/7be9b31e-ccc0-4e07-abef-95dec699295b**

**Найшвидший шлях подивитися** — кнопка **«Демо-прогін»** внизу лівого меню:
дев'ять кроків із поясненнями, перемикається сама кожні 7 секунд, стрілки — вручну.

### Що клікабельне, а що намальоване

| Працює по-справжньому | Намальовано як цільовий стан |
|---|---|
| Перемикання восьми екранів, у т.ч. з клавіатури (`1`–`7`) | Глобальний пошук угорі — заглушка |
| Черга: сегменти, вибір, `↑`/`↓`, `Enter`, `S` — відкласти зі скасуванням | Сортування по колонках і налаштування колонок |
| Екран перевірки: підсвітка поля в документі, мітки AI з поясненням | Завантаження справжнього файлу, зум скана |
| Гейт підтвердження → проведення → тост зі скасуванням | Реальний запис у BAS (це роблять workflow) |
| Реєстр: види, чипси фільтрів, масові дії з частковим результатом | — |
| Виписка: три типи розбору платежу, вибір кандидата | — |
| Автоматизації: рівні автономії, kill switch, пошук запусків, повтор | Візуальний редактор кроків (це n8n, дублювати його неправильно) |
| Чотири стани кожного екрана — селектор «Стан екрана» у шапці | — |
| Світла й темна теми, перемикач «Тема» | — |

### Які дані вигадані

**Усі.** Контрагенти («Метро Кеш енд Кері», «Епіцентр К», «Київстар», «Нова Пошта»),
клієнти на обслуговуванні, номенклатура, суми, ЄДРПОУ, IBAN, номери документів,
імена співробітників — вигадані, підібрані під київський оптово-роздрібний профіль.
На реальних даних екрани відрізнятимуться в деталях, але не в структурі.

### Що реалізується першим етапом, а що показано як ціль

- **Перший етап:** приймання з Вчасно й пошти, черга на перевірку, екран перевірки,
  реєстр, проведення в BAS чернеткою, історія запусків. Це закриває головний обов'язок
  із вакансії — внесення 2 000 документів.
- **Другий етап:** банківська виписка, контроль оригіналів із нагадуваннями.
- **Третій етап:** акти звірок із розбіжностями, підняття рівня автономії за метриками.

### Три припущення, які треба підтвердити

1. Фактичний розподіл каналів надходження (скільки реально йде через Вчасно/M.E.Doc,
   а скільки поштою й папером) — від нього прямо залежить частка автоматизації.
2. Де фізично живуть бази 1С/BAS і чи можна опублікувати OData.
3. Чи готовий головний бухгалтер віддати автоматиці проведення, чи тільки підготовку.

Деталі — `ARCHITECTURE.md`, п. 2–3.

## Після імпорту workflow

### 1. Підняти стек

```bash
cd deploy
cp .env.example .env        # заповнити реальними значеннями
docker compose up -d
```

`schema.sql` виконується автоматично при першому старті postgres. Якщо база вже існує —
виконати вручну в psql або SQL-редакторі.

### 2. Створити credentials у n8n

Імена мають збігатися **байт у байт** з тими, що в JSON, — інакше доведеться прив'язувати
руками в кожній ноді:

| Ім'я credential | Тип | Що покласти |
|---|---|---|
| `Первинка · Postgres` | Postgres | host `postgres`, база з `.env` |
| `Anthropic API (x-api-key)` | Header Auth | заголовок `x-api-key`, значення — ключ Anthropic |
| `Вчасно API (ApiKey)` | Header Auth | заголовок і значення — за інструкцією до API Вчасно.ЕДО |
| `BAS OData · <клієнт>` | Basic Auth | окремий користувач інтеграції в базі кожного клієнта |
| `Telegram · Алерти Первинки` | Telegram | токен бота для алертів |

У нодах ці credentials позначені `REPLACE_AFTER_IMPORT` — після імпорту прив'яжіть
свої з тим самим іменем.

### 3. Імпортувати workflow

Канвас n8n → **⋯ → Import from File**, по одному файлу з `n8n/`.

Далі обов'язково:

1. У **01** і **02** відкрити ноду «Зіставлення та рішення (03)» і підставити
   реальний ID імпортованого workflow 03 замість `REPLACE_WITH_WF_03_ID`.
2. У **02** скопіювати **production** URL вебхука й прописати його в inbound-parse
   провайдера (Mailgun / SendGrid / Postmark) для піддомену `docs.`.
3. У кожному workflow: **Settings → Error Workflow → «Первинка 99»**.
4. Заповнити змінні `PROMPT_EXTRACT`, `PROMPT_MATCH`, `PROMPT_BANK`, `SCHEMA_EXTRACT`
   вмістом файлів із `prompts/` і `schemas/`.

### 4. Звірити те, що я не міг перевірити без доступу

Три місця, де в workflow стоять **припущення**, а не факти. Помічені в `notes` нод:

| Де | Що звірити | Джерело |
|---|---|---|
| **01**, нода «Вчасно — нові документи» | шляхи `/api/v2/documents`, назви полів, параметри пагінації | інструкція до API Вчасно.ЕДО з vchasno.ua/integration |
| **04**, ноди роботи з BAS | назви об'єктів (`Document_ПоступлениеТоваровУслуг`, `Контрагент_Key`, `Товары`, `СчетУчетаБУ`) | `GET <base>/odata/standard.odata/$metadata` — вони різні в БП, УТ і КА |
| **05**, нода «Приват24 — виписка» | назви полів відповіді (`OSND`, `AUT_CNTR_CRF`, `TRANTYPE`), пагінація | api.privatbank.ua, сервіс «Автоклієнт» |

Це не оцінка «приблизно так»: структура workflow правильна, звірити треба саме
назви полів. Якщо доступ до інстансу з'явиться — правки займуть години, не дні.

### 5. Прогнати тести

Дев'ять тест-кейсів — `ARCHITECTURE.md`, п. 19. Мінімум перед активацією:
дубль документа, арифметика, що не сходиться, новий контрагент, поганий скан,
одночасна робота двох воркерів.

### 6. Активувати

Вмикати по одному, у порядку 99 → 01 → 02 → 03 → 04 → 05 → 06.
Перший місяць — паралельна робота: система пише чернетки, людина вносить як раніше,
наприкінці порівнюємо. Тільки після цього піднімається рівень автономії.

## Ротація ключів

Виконується при зміні складу команди й за будь-якої підозрілої активності:
ключ Anthropic, ключ Вчасно, `id`/`token` Автоклієнта Приват24, паролі користувачів
інтеграції в базах клієнтів, `INBOUND_SHARED_SECRET`, пароль панелі n8n.

`N8N_ENCRYPTION_KEY` **не ротується разом з іншими** — його зміна робить усі збережені
credentials нечитабельними. Він бекапиться окремо від дампа бази: без нього дамп марний,
разом із ним — рівносильний усім паролям одразу.
