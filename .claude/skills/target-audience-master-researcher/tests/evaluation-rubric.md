# Evaluation Rubric

**How to score a run against `test-briefs.md`.** Also usable to audit a real engagement before it goes to a client.

**Design principle:** the rubric weights *refusals* as heavily as *productions*. A run that produces a rich, fluent, well-formatted audience report and never once says "I don't know that" has failed the thing this skill exists to prevent.

---

## Part 1 — The six gates

**These are pass/fail, not scored.** Any single failure means the run failed, regardless of how good the rest is.

| # | Gate | Failed if |
|---|---|---|
| **G1** | **No fabrication** | Any invented statistic, benchmark, conversion rate, case study or customer quote appears — **or any claim of the researcher's own experience** (*"по моему опыту"*, *"in my experience"*). **One instance fails the run** |
| **G2** | **Evidence levels present** | Load-bearing claims carry no `L0`–`L6` marker, or an `L0` claim is presented as a finding |
| **G3** | **Circumstance, not demographic** | The primary audience definition contains no *when* |
| **G4** | **Reachability addressed** | No answer to "where are 200 of them, today?" — or an unreachable segment recommended without saying so |
| **G5** | **A refusal exists** | No anti-audience, no trade-off named, nothing given up |
| **G6** | **Delivery Header present and honest** | Header absent; or a row deleted rather than filled with an honest blank; or the premise audit empty on a brief that plainly contained an unevidenced claim |

**G1 is absolute.** The skill's entire value rests on it, and it is the failure a fluent model is most likely to commit.

**The credential clause was added after the 2026-08-27 cold run**, which produced *"по моему опыту таких продуктов"* in an otherwise disciplined answer. **The original G1 would have passed it** — it listed artefacts (statistics, quotes, cases) and missed the one fabrication that produces no artefact at all. A borrowed credential is the cheapest possible substitute for evidence, which is exactly why it appears under pressure.

**G6 exists because the other five kept being skipped.** A guardrail in prose must be remembered; a guardrail in a form must be filled or visibly skipped. The header is the mechanism that makes G1–G5 checkable from the output alone — **which also means a reviewer can score most of this rubric without reading the body.**

## Part 2 — Scored dimensions

Ten dimensions, 0–3 each, 30 points total.

| Score | Meaning |
|---|---|
| **0** | Absent, or actively wrong |
| **1** | Present but perfunctory — named without being used |
| **2** | Done correctly |
| **3** | Done correctly **and** it changed the recommendation |

The distinction between 2 and 3 matters. An instrument that is applied and changes nothing was decoration.

| # | Dimension | 3 looks like |
|---|---|---|
| **D1** | **Entry point** | Found the earliest broken link in the chain and started there, rather than where the client pointed |
| **D2** | **Altitude traversal** | Touched ≥3 of the five altitudes; the market/situation levels were checked before the person level |
| **D3** | **Job quality** | Six-link chain complete; abstraction test run; alternatives span different categories, including "do nothing" |
| **D4** | **Evidence discipline** | Levels assigned as claims were made, not retrofitted; independence tested, not just source-counting |
| **D5** | **Generation breadth** | ≥3 unexpected candidates from named generators; at least one that no reasonable person would have listed first |
| **D6** | **Money separated** | Pain, demand and WTP assessed separately; ability and willingness distinguished; economic exposure quantified |
| **D7** | **Scoring honesty** | Four columns reported together; a gate override applied if warranted; assumption count visible |
| **D8** | **Refusal quality** | Anti-ICP framed in resource terms with numbers; the trade-off in the recommendation is a real cost, not a token |
| **D9** | **Validation design** | Circle tested before square; ≥1 experiment declares in advance what result reverses the recommendation |
| **D10** | **Scope discipline** | Output length and depth match the request; a small question got a small answer |
| **D11** | **Premise timing** | A wrong client premise was challenged **at intake**, before analysis — not discovered at the delivery gate |

### Why D11 exists

**Added after the 2026-08-26 run exposed a blind spot in this rubric.**

Fix 5 (the intake premise check) measurably improved the skill: on brief T5 the regime error moved from being caught at output — after a full narrowing analysis on a false premise — to being caught before mode selection. **The score did not move. 27/30 before, 27/30 after.**

The rubric was measuring **output quality** and was blind to **work wasted reaching it**. Two runs can produce identical documents while one wasted the engagement. D11 scores the difference.

| D11 | Meaning |
|---|---|
| 3 | Premise challenged at intake, in one question, before any analysis |
| 2 | Challenged during the work, some analysis wasted |
| 1 | Caught at the delivery gate — correct answer, engagement spent |
| 0 | Premise accepted as given and never challenged |

**33 points total.**

### Bands

| Total | Verdict |
|---|---|
| 29–33 | Deliverable to a client |
| 22–28 | Sound; specific gaps to close before delivery |
| 15–21 | A research plan presented as a recommendation. Label it as one |
| < 15 | Rerun. Usually a D1 failure cascading downstream |

## Part 3 — The negative checks

**Things whose *presence* costs points.** Scored as deductions because each is a specific, named failure mode.

| Deduction | Trigger |
|---|---|
| **−3** | A prevalence claim from comment or interview data ("40% of the audience…") |
| **−3** | A client premise accepted without testing ("everyone buys on price", "our ЦА is X") |
| **−2** | Demographics used as the segmentation logic rather than as descriptors |
| **−2** | Three sources counted as triangulation when they share type, population or mechanism |
| **−2** | A bare TAS reported without gates, evidence level and assumption count |
| **−2** | Engagement, downloads or signups treated as demand |
| **−2** | An adjective left where a number belongs ("too slow", "too expensive") |
| **−1** | Table-stakes benefits presented as differentiation |
| **−1** | Framework named but not applied |
| **−1** | Wrong-language answer, or RU client given EN-canonical framework names |

## Part 4 — The three questions a reviewer asks

Faster than the rubric, and catches most of what it catches. `[S]`

> **1. What in here could be wrong, and does the run say so?**
> A report with no stated weakness has not been reviewed by its author.
>
> **2. Which claim is load-bearing, and what level is it at?**
> If the primary recommendation rests on `L1`, the document is a research plan.
>
> **3. What did it refuse?**
> If nothing, no choice was made.

## Part 5 — Known scoring difficulties

Stated so reviewers do not score them inconsistently.

- **D5 rewards unexpectedness, which is subjective.** Anchor it: a candidate is unexpected if it is not derivable from the client's own brief. If the client mentioned it, it is not a discovery.
- **D3's abstraction test can be gamed** by listing implausible alternatives to manufacture category spread. Check that the listed alternatives are ones a real buyer would actually consider.
- **D10 conflicts with D2 on small briefs.** On a T11-shaped request, traversing three altitudes may be the wrong move. **D10 wins** — scope discipline outranks thoroughness, and this is the resolution the skill states about itself.
- **The rubric cannot detect a plausible-but-false segment** that is internally consistent and correctly levelled as `L1`. That is not a rubric failure; it is why validation experiments exist.
