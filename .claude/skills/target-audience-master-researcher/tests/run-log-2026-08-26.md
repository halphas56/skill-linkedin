## Hypothesis 1 — the examples are stale

**Method.** Grep all five legacy examples for the instruments added in research passes 3–6.

```
                                    L0-L6  TAS  4-forces  mkt-map  abstraction  seg-object
agency-service-example.md             0     1      0         0         0           0
b2b-saas-example.md                   0     0      0         0         0           0
expert-course-example.md              0     0      0         0         0           0
local-business-example.md             0     0      0         0         0           0
unexpected-audience-example.md        0     0      0         0         0           0
```

**Result: CONFIRMED, and it is the most serious defect found.**

Across **1,362 lines** of worked examples: zero evidence levels, zero four-forces diagnostics, zero market maps, zero abstraction tests, zero segment objects. One incidental mention of "TAS".

**Why this matters more than it looks.** Examples are the highest-leverage content in a skill because they are what gets imitated. Five stale examples do not merely fail to teach the current method — they **actively teach the superseded one**, and they outnumber any single instruction file.

**Action taken.** Wrote `../examples/00-reference-engagement.md` (~430 lines) as the reference implementation: a channel business run end to end through market definition → market map with quantified leverage → JTBD six-link → four forces → generation including negative jobs → evidence levels throughout → TAS with sources per cell → anti-ICP → circle-before-square validation → named trade-off → stated limitations.

**Second action taken.** Each of the five legacy examples received a **"Delta to the current method"** section — 15–20 lines naming what the current instruments would change **for that specific business**, not generically.

This was chosen over a full rewrite deliberately. Rewriting five examples to the new standard would have produced ~2,000 lines largely re-demonstrating what the flagship already shows, in different domains. The delta approach preserves each example's distinct teaching point (RU output conventions, radius-as-first-axis, gate-blocked handling, discovery-from-review-data) while **teaching the difference explicitly** — which is arguably more instructive than a clean rewrite, because a reader sees both the old reasoning and what it was missing.

Sample of what the deltas surfaced, per case:
- **Threadline (B2B SaaS):** the real incumbent is *the monthly review meeting*, which no feature comparison surfaces; signups are `L6-big` and prove nothing until usage data exists
- **Northline (agency):** eleven projects all from referrals makes **the referrer a leverage junction**, not a channel — entirely unaddressed in the original
- **Pilates studio (RU):** the *"врач посоветовал"* entry point opens a partnership channel with physiotherapists that no demographic analysis reaches
- **Fieldnote:** reviews contain buyers only, so a review-derived finding caps at `L3` — one source type, however many reviews
- **Expert course (RU):** *"стать финдиректором"* is a **life theme**, not a job — important, and incapable of triggering a purchase

**Residual defect.** The legacy examples still *lead* with pass-1 reasoning; a reader who stops before the delta section gets the old method. Mitigated by the delta being clearly marked and by `00-reference-engagement.md` being named as the standard in the routing table. **Downgraded from High to Medium, not closed.**

## Internal consistency checks

Four checks run against the file system. Three passed.

### ✅ Segment counts are consistent
Twelve files reference segment counts. Two systems coexist — **10–20 candidates** (top-down) and **30–50 micro-segments → 7–10 clusters** (bottom-up) — and they are explicitly reconciled in `../knowledge/market-mapping.md` §10 and `../SYNTHESIS.md` §4. **No contradiction.**

### ✅ Sample-size floors are consistent
`~20–30 reviews · ~10 interviews · ~10 call recordings · ~10 search queries · ≥100 comments` appear identically across `voice-of-customer.md`, `interview-and-survey-kits.md`, `avatar-from-comments.md`, `evidence-ladder.md`, `frameworks.md` and the research report. **No drift.**

### ✅ No stale step cross-references
The tier restructuring of `../SKILL.md` removed all `Step N` references from its reference table. Previously these pointed at fast-path numbering while a reader would naturally check the manual's numbering, which differs (17 steps incl. 2b/2c/5b vs 19 fast-path items). **Grep confirms zero remaining.**

### ⚠️ Finding: six of nineteen scoring criteria never feed the TAS
Criteria **#7, #11, #12, #13, #14, #19** appear in the 19-criterion diagnostic table but in no TAS variable. Only #7 was documented as an intentional exception; the other five were silently absent.

**Not a calculation error** — the TAS is deliberately compact for cross-engagement comparability. But a reader scoring nineteen criteria and finding five that never surface would reasonably assume a bug.

**Fixed.** `../templates/scoring-matrix-template.md` Part 0 now carries a table stating which six are diagnostic-only and why each was excluded, plus the instruction to argue a decisive one **in words rather than inflating the total**.
