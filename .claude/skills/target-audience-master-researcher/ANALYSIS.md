Дата: 2026-08-31 · Аудит выполнен при переносе архива `CA.zip` в git.
Предмет аудита — **упаковка и работоспособность скилла**, а не качество метода.
Метод самим автором уже отревьюен в `README.md` → «What still needs manual validation».

Импорт сделан побайтово (md5 всех 50 файлов совпадают с архивом). Ни один дефект
из перечисленных ниже **не исправлен** — коммит импорта оставлен чистой базой,
чтобы каждое улучшение читалось отдельным диффом.

## 1. Блокеры — скилл в текущем виде загружается некорректно

### A1. `description` — 1660 символов при жёстком лимите 1024 ⛔

Официальный валидатор (`skill-creator/scripts/quick_validate.py`) на скилле падает:

```
$ python3 quick_validate.py target-audience-master-researcher
Description is too long (1660 characters). Maximum is 1024 characters.
```

**Почему это критично.** `description` — единственная часть скилла, которая лежит
в контексте модели постоянно; именно по ней принимается решение «брать скилл или нет».
Всё, что за 1024 символа, **обрезается**. Обрезается с конца — а в конце здесь
лежит весь русский триггерный блок, 32 фразы от `целевая аудитория` и `ЦА`
до `кому НЕ продавать`.

Это не гипотеза, а арифметика: 1024-й символ приходится ровно на

> `...consulting, marketplaces, mobile apps, info products and subscriptions. Wo` ⟵ **обрыв**

— то есть **все 32 русские фразы отрезаются целиком, до единой.** Скилл, половина
примеров и один целый модуль (`knowledge/ru-market-playbook.md`) которого написаны
по-русски, на русские запросы не поднимается.

**Готовая замена — 942 символа, 125 слов** (лимит рекомендации: 100–200 слов):

```yaml
description: >
  Finds the target audience that will actually pay, stay and spread — including the
  non-obvious segments nobody else is marketing to. Generates 10–20 candidate segments,
  scores them on evidence, maps where each one gathers, judges whether they can be
  reached for free, and builds positioning around the winner. Use for ICP definition,
  buyer personas, a customer avatar built from real comments, jobs-to-be-done analysis,
  customer-pain discovery and validation, voice-of-customer language, audience
  segmentation, willingness-to-pay, niche selection, comparing two audiences, or
  diagnosing why marketing is not converting. Works for SaaS, courses, agencies, local
  business, consumer products, consulting and marketplaces, in English and Russian —
  целевая аудитория, ЦА, портрет клиента, аватар клиента, сегментация, кастдев, custdev,
  боли клиентов, JTBD, где искать клиентов, готовность платить, выбор ниши,
  кому продавать, неочевидная аудитория.
```

Что вырезано и почему: список отраслей ужат (перечисление 10 вертикалей не улучшает
матчинг — модель обобщает), убраны синонимичные русские хвосты вокруг «боли»
(`найти боли` / `проверить боли` / `приоритизация болей` покрываются `боли клиентов`),
убраны `анализ отзывов` / `что пишут в комментариях` (покрываются `аватар клиента`).
**Ключевое отличие: теперь русские триггеры реально доезжают до модели, а не обрезаются.**

### A2. Шаг 18 Fast path («Ship it as a PDF») не выполнится из коробки ⛔

`SKILL.md` заканчивает каждую поставку командой:

```
python tools/md2pdf.py REPORT.md -o REPORT.pdf --title "..." --stats "..."
```

и формулирует это как обязательное («A markdown file in a repo is not a deliverable
a client reads»). Проверено в этом контейнере — падает дважды:

1. `import markdown` → `ModuleNotFoundError: No module named 'markdown'`.
   Зависимость нигде не объявлена: нет ни `requirements.txt`, ни строки в `SKILL.md`.
2. Поиск браузера. `CHROME_CANDIDATES` — это четыре Windows-пути, три `/usr/bin/*`
   и один macOS. В этом окружении Chromium лежит в `/opt/pw-browsers/chromium`
   и **не в `PATH`**, поэтому и `shutil.which()` его не находит → `sys.exit(...)`.

Скилл написан на Windows-машину, где оба условия выполнялись сами собой. На любой
другой обязательный последний шаг workflow ломается.

**Что сделать:** объявить зависимость (`requirements.txt` + строчка в `SKILL.md`),
добавить в `CHROME_CANDIDATES` `/opt/pw-browsers/chromium` и чтение
`$CHROME_PATH` / `$PLAYWRIGHT_BROWSERS_PATH`, и — главное — сделать шаг 18
деградирующим: если PDF собрать нельзя, отдать markdown и сказать почему,
а не падать в конце четырёхчасовой работы.

## 2. Существенное, но не блокирующее

### B1. Смешанные переводы строк — 11 файлов CRLF, 39 файлов LF

CRLF: `SKILL.md`, `SYNTHESIS.md`, `OPERATING-MANUAL.md`, `research/frameworks.md`,
`knowledge/pain-discovery.md`, `checklists/red-flags-checklist.md`,
`tests/{COLD-RUN,evaluation-rubric,run-log-2026-08-26-execution,run-log-2026-08-26-fixes,run-log-2026-08-27-cold}.md`.

Сейчас это не ломает ничего (фронтматтер парсится), но в git это мина: любой,
кто отредактирует такой файл на Linux/macOS, получит дифф «изменено 227 строк»
вместо «изменено 2». Правится один раз — `.gitattributes` с `* text=auto eol=lf`
плюс разовая нормализация. Сделано отдельным коммитом, потому что дифф будет
шумный и его не надо смешивать с содержательными правками.

### B2. `research/` — 392K, из них один файл на ~39 000 токенов

| Файл | ≈ токенов |
|---|---|
| `research/target-audience-research-report.md` | ~39 200 |
| `research/source-map.md` | ~20 400 |
| `research/frameworks.md` | ~17 600 |

Весь скилл — ~180 000 токенов markdown, и **43% из них лежит в `research/`**,
который сам `SKILL.md` (Tier 5) помечает как «consult, don't read».
Исследовательский отчёт на 39k токенов физически нельзя загрузить в рабочую сессию
целиком — а ссылка на него из Tier 5 выглядит как приглашение это сделать.

Это не ошибка архитектуры (прогрессивное раскрытие — правильный выбор), а
незакрытый риск: **у Tier 5 нет входной точки уровня «оглавление»**. Чтобы найти
нужный фреймворк в `frameworks.md`, надо знать, что он там есть.
Дешёвое улучшение: `research/INDEX.md` — таблица «вопрос → файл → якорь», 1–2 экрана.

### B3. Тесты написаны той же сессией, что писала скилл

Автор это фиксирует честно (`README.md`: «the session that ran them wrote the skill —
contaminated on recall»), и в `tests/` даже лежит контрольная группа
(`run-log-2026-08-27-cold.md`, тот же бриф без скилла, 18/33).

Но вывод из этого прямой: **12 из 13 прогонов проверяли связность, а не обучаемость.**
`tests/COLD-RUN.md` — готовый 10-минутный кит, который эту проблему закрывает,
и он **ни разу не был запущен незаражённой сессией**. Это самая дешёвая проверка
из всех оставшихся и первое, что стоит сделать после переноса.

### B4. Карта файлов в `README.md` больше не соответствует репозиторию

`README.md` рисует дерево от `CA/` с папкой `target-audience-master-skill/`.
После переноса корень другой. Также `research/source-map.md` (строки 433, 621)
ссылается на исходники по путям вида `D:\книги\...` — это личный диск автора,
воспроизвести цитату по такой ссылке никто не сможет. Не критично для работы,
но для внешнего читателя источник фактически непроверяем.

### B5. Два разных `md2pdf.py` в одном репозитории

| Файл | Движок | Назначение |
|---|---|---|
| `scripts/md2pdf.py` (168 строк) | WeasyPrint | верстает `strategy/*.md` |
| `.claude/skills/.../tools/md2pdf.py` (407 строк) | headless Chrome | верстает поставки скилла |

Одинаковое имя, разные зависимости, разное поведение. Пока их не путают — терпимо;
объединять **не стоит** (у скилловой версии есть обложка, TOC, нумерация страниц
и кириллические шрифтовые стеки, которых нет у репозиторной). Стоит только
переименовать одну из них, чтобы разница читалась из имени.

## 3. Что в скилле сделано сильно (не трогать при рефакторинге)

Это не комплименты, а список того, что легко сломать «улучшением».

1. **Архитектура «один скилл, много модулей»** — в `SKILL.md` явно написано, что
   фронтматтер только здесь и что добавление модуля ≠ добавление скилла.
   На 17 800 строк это единственный способ остаться загружаемым.
2. **Маршрутизация по тирам вместо оглавления.** Tier 0 «всегда» → Tier 5
   «consult, don't read» — модель получает бюджет, а не список.
3. **Evidence Ladder как принудительный протокол.** Скилл прямо адресует то,
   как LLM ломается на такой задаче: выдумывает правдоподобную боль, пишет её
   гладко, и гладкость принимают за доказательство. L0–L6 делает этот отказ
   видимым. Это самая ценная часть скилла.
4. **Разделение двух шкал** (Pain Strength vs Commercial Opportunity) с запретом
   их смешивать — ловит классическую ошибку «сильная боль без денег».
5. **Отказ от бенчмарков конверсии.** Явно: «No conversion benchmarks appear
   anywhere in this skill». Это редкая дисциплина, и она правильная.
6. **Контр-доказательство внутри корпуса.** Байрон Шарп противоречит посылке
   остального корпуса, и скилл обязан назвать режим (focus/reach) до рекомендации.
7. **Раздел «What still needs manual validation» в `README.md`.** 18 строк
   собственных слабых мест с указанием, что с каждым делать. Это лучшее, что
   есть в документации скилла — сохранить и поддерживать.
8. **Все относительные ссылки живые** — проверено программно: 42 ссылки,
   37 уникальных целей, 0 битых.
